# Solo PR Flow

個人開発では「PR を作る → CI を待つ → マージ → 後片付け」が毎回同じ。
このスキルはその一連を確認なしで完走させる。

**このスキルの本体は下の「停止条件」である。** 自動マージは取り消しが難しく、
公開リポジトリなら履歴にも残る。だから「進めてよい条件」より
**「進めてはいけない条件」を先に、網羅的に**判定する。

---

## 停止条件（1つでも該当したら自動マージしない）

該当したら、**該当した条件名を挙げて**利用者に判断を仰ぐ。黙って進めない。

### A. 情報が取れないとき

**確認できなかった項目は「該当する」とみなす。** APIエラー、権限不足、タイムアウト、
どれも同じ扱い。**分からないなら止まる**のが既定動作。

### B. リポジトリが自分のものでない / 一人のものでない

| # | 条件 | 判定材料 |
|---|---|---|
| B1 | 自分が管理者でない | `permissions.admin != true` |
| B2 | オーナーが組織 | `owner.type == "Organization"` |
| B3 | コラボレーターが2人以上 | コラボレーター一覧 |
| B4 | コミット著者が2人以上 | 直近100件のコミット著者（bot は除く） |
| B5 | CODEOWNERS がある | `.github/CODEOWNERS` / `CODEOWNERS` / `docs/CODEOWNERS` |

B3〜B5 は「レビューできる他人がいる」証拠。いるなら自動マージの前提が崩れる。

### C. 他人が見ている

| # | 条件 | 判定材料 |
|---|---|---|
| C1 | Star が2以上 | `stargazers_count >= 2`（1は自分の自己Star） |
| C2 | Fork されている | `forks_count >= 1` |
| C3 | Watcher が2以上 | `watchers_count >= 2` |

無名のうちは 0〜1。**他人の痕跡が1つでも出たら、そのリポジトリはもう「自分だけのもの」ではない。**

### D. リポジトリの状態が特殊

| # | 条件 |
|---|---|
| D1 | `archived` が true |
| D2 | `fork` が true（他人のプロジェクトの派生） |
| D3 | `disabled` が true |

### E. PR 自体の問題

| # | 条件 | 対応 |
|---|---|---|
| E1 | draft のまま | 勝手に外さない。外してよいか尋ねる |
| E2 | PR の作成者が自分（またはこのセッションの作業）でない | 他人の PR は絶対にマージしない |
| E3 | base が既定ブランチでない | 意図を確認する |
| E4 | コンフリクトあり | 解決して push。一意に決まらないときだけ尋ねる |
| E5 | CI が失敗 | 直して push。直せないなら理由を1〜2行で報告 |
| E6 | CI が実行中 / queued | **待つ。ポーリングしない。** 完了通知で起きて再判定 |
| E7 | CHANGES_REQUESTED のレビューがある | 指摘に対応する |
| E8 | `protected_paths` に触れている | 該当ファイル名を挙げて可否を尋ねる |

`protected_paths` の既定は `.github/workflows/`。**CI 定義を書き換える PR が自動で通ると、
安全装置そのものを無効化できてしまう**ため。

### F. opt-in がない

`.claude/solo-pr.json` が無く、利用者がこのセッションで自動マージを明言してもいない。

この場合だけは、1回こう尋ねてよい:

> このリポジトリを自動マージ対象にしますか? `.claude/solo-pr.json` を作れば以後は確認なしで進めます。

`assets/solo-pr.json` がテンプレート。

## 停止条件に1つも該当しないとき

**尋ねずにマージする。** それがこのスキルの存在理由。確認を挟むなら意味がない。

1. `merge_method`（既定 `squash`）でマージ。コミットメッセージは PR タイトルを使う
2. `delete_branch`（既定 true）ならリモートブランチを削除
3. ローカルを既定ブランチに切り替えて pull、マージ済みローカルブランチを削除
4. PR の監視を購読していれば解除する
5. 1〜3行で報告。PR番号・マージ方式・後片付けの結果だけ。長い要約は書かない

## 設定 `.claude/solo-pr.json`

```json
{
  "auto_merge": true,
  "merge_method": "squash",
  "delete_branch": true,
  "protected_paths": [".github/workflows/"]
}
```

| キー | 既定 | 意味 |
|---|---|---|
| `auto_merge` | `true` | false なら判定だけして止まる |
| `merge_method` | `"squash"` | `squash` / `merge` / `rebase` |
| `delete_branch` | `true` | マージ後にリモートブランチを削除 |
| `protected_paths` | `[".github/workflows/"]` | ここに触れる差分は必ず確認 |
| `no_checks` | `"proceed"` | チェックが1つも無いとき `proceed` / `ask` |

**停止条件は設定で無効化できない。** 設定できるのは進め方だけ。

## 原則

- **停止条件を1つでも確認し忘れたら、自動マージしてはいけない**
- **確認できなかった項目は該当扱い。** 分からないなら止まる
- **停止条件は設定より強い。** opt-in があっても停止条件が優先する
- **CI 待ちで sleep やポーリングをしない。** 完了通知で起きて再判定する
- **main へ force push しない。** どんな状況でもしない
- 停止条件に該当しないなら**尋ねずにマージする**
- 「たぶん大丈夫」で進めない。根拠が無いのは停止条件 A に該当する

## 判定の順序

リポジトリ側（A〜D、F）を先に、PR側（E）を後に見る。
リポジトリが対象外なら PR を調べる意味がない。往復を減らせる。

具体的なコマンドと API フィールドの対応は `references/commands.md` を読む。
