# 公開情報の精査

公開リポジトリで見えるのはファイルの今の中身だけではない。履歴の追加行、消したファイル、
コミットメッセージ、著者のメールと時差、Issue と PR の本文とコメント、リリース、説明文、
Wiki、Actions のログ。どれも誰でも読める。

答える問いは2つ。

| 問い | 見る所 | 見つかったときの意味 |
|---|---|---|
| これから出すものに、公開してはいけないものが無いか | 作業ツリー、差分 | まだ止められる。伏せれば済む |
| すでに出ているものに、何があるか | 履歴、GitHub 側 | もう見えている。伏せても fork やキャッシュに残る。消すかは利用者が決める |

## 鍵の走査との違い

| | secret-leak-check | public-audit |
|---|---|---|
| 見るもの | API キー、トークン、秘密鍵、認証情報付きの URL | 名前、連絡先、ID、費用、内部の場所、リンク、画像、著者、GitHub 側 |
| 見つかったら | 先にローテート | 伏せる。すでに公開のものは利用者が決める |
| 判定 | 形で機械が決められる | 公開してよいかは人が決める。走査は候補を出す |

公開前は両方を回す。

## 手順

### 1. 範囲を決める

| 状況 | 範囲 |
|---|---|
| コミット前、PR の前 | `--diff`（未コミット）か `--diff origin/main..HEAD` |
| private を public にする前 | `--all <owner/repo>`。履歴と GitHub 側を省くと公開の意味が無い |
| すでに public で、月1の見直し | `--all <owner/repo>` |
| 「書いてしまった」 | `--history` で、押し出された範囲を見る。push 済みなら「すでに公開」 |

### 2. 走査する

```bash
.claude/skills/public-audit/scripts/audit.py --diff                   # 未コミットの変更
.claude/skills/public-audit/scripts/audit.py --diff origin/main..HEAD # PR の差分
.claude/skills/public-audit/scripts/audit.py --tree                   # 作業ツリー（追跡していないファイルも）
.claude/skills/public-audit/scripts/audit.py --history                # 全コミット。追加行、メッセージ、著者、消したファイル
.claude/skills/public-audit/scripts/audit.py --github <owner/repo>    # 説明、Issue と PR の本文とコメント、リリース、設定
.claude/skills/public-audit/scripts/audit.py --all <owner/repo>       # 上の全部
```

拾うもの: メールアドレス、セッションと Routine の ID とセッションの URL、利用者名入りのパス、
郵便番号、電話番号、私有アドレスと内部ホスト名、グローバルアドレス、非公開サービスへのリンク
（Google ドキュメント、Notion、Slack、Figma、Atlassian）、費用の数字、認証情報のファイル名と `.env`、
データのファイル（sql、csv、har、log）、画像と動画と PDF の一覧、非公開リポジトリの名前（一覧がある
とき）。履歴では著者ごとのメールと時差、一度でも追加した認証情報のファイル名も出す。
鍵やトークンは `secret-leak-check` の `scan.py` が見る。重ねて見ない。

検出（重大・注意）があれば終了コード 1。同じ値は1件にまとめて場所を並べる。1つの URL が
全コミットに入っていても、決めるのは1件。

### 3. 判定する

検出は漏れではない。1件ずつ見て、公開してよいものかを決める。

- 公開してよいか決めるのは利用者。走査が拾ったものを「問題ない」と AI が決めない。判断がつかないものは伏せる側に倒し、`❔` で1行聞く
- 例示（`example.com`、RFC 5737 のアドレス、`<owner>/<repo>`）、返信不可のアドレス、容器の既定の名前（`/home/user/`）は既定で拾わない
- 意図して置いた例は、行末に `public-audit: ignore` を書くか、`.publicallow` に1行足す（正規表現は値に、`path:<glob>` はファイルに当たる）。足す前に、それが本当に公開してよいものか見る

### 4. 報告する

値そのものは報告に書かない（走査の出力は既定で伏せる。`--show` は手元の端末で自分だけが見るとき）。
値が同じものは1件に数え、「まだ止められる」と「すでに公開」を分けて数える。

```
重大 2 / 注意 0 / 情報 3
まだ止められる 0 / すでに公開 2
  セッションの URL   コミットメッセージ 96 箇所、PR 本文 N 件   → 以後は付けない。履歴は利用者が決める
  著者のメール        85 コミット                              → 以後は noreply に。履歴は利用者が決める
```

3行を超えるなら Markdown のファイルに書いて `★` で渡す。検出ゼロでも「安全」とは言わない。
「このルールでは検出されなかった」と言い、人が見るもの（`references/checklist.md`）を1行添える。

### 5. 伏せる

伏せ方は `references/checklist.md` の表に従う。非公開リポジトリの名前は `<owner>/<repo>`、
メールは消すか noreply、ID は日付と題で指す、費用の数字は非公開の場所へ、内部の場所は例示用の値へ。
伏せたあと `--diff` をもう一度回し、伏せ漏れが無いことを見てから PR にする。

すでに公開のものは、伏せても残る。履歴を書き換えるか、以後の分だけ止めるかは利用者が決める。
材料（件数、書き換えると変わるもの、残る所）を出して `❔` で聞く。聞かずに書き換えない。

## 非公開の名前の一覧

非公開リポジトリの名前は、形では拾えない。一覧を渡すと拾う。

- 置き場所は必ずリポジトリの外。`~/.config/public-audit/names.txt`、環境変数 `PUBLIC_AUDIT_NAMES`、
  または `--names <file>`。リポジトリに入れると、一覧そのものが漏れる
- 1行1つ。`owner/repo` か名前だけ。4文字未満の名前は普通の語とぶつかるので、`owner/repo` の形で書く
- 手元の端末では GitHub CLI で作れる

```bash
mkdir -p ~/.config/public-audit
gh repo list <owner> --visibility private --limit 200 --json nameWithOwner -q '.[].nameWithOwner' > ~/.config/public-audit/names.txt
```

クラウドのセッションではこの一覧を作れない。中継がリポジトリ単位の API しか通さない
（2026-10-18 に確かめた。`user/repos` は `sessions are bound to their configured repositories`）。
一覧が無いときは走査が「非公開の名前は検査していない」と出す。その1行を報告に残す。

## 人が決めること

- 何を公開してよいか（ハンドル、著者名、時差、費用の数字）
- 履歴を書き換えるか、以後の分だけ止めるか
- GitHub 側の設定（メールを隠す、Wiki を切る、ログの保存期間）。AI からは変えられない
- 名前の一覧に何を足すか

決まったことは、そのリポジトリの CLAUDE.md に「書かないもの」として1行で残す。
AI が自分で決めてよいのは、既定の伏せ方で伏せることだけ。

## 定期に回す

public なリポジトリは月に1度 `--all` を回す。`dev-report` の月報を書くときが区切り。
Ciel 自身は `skill-upkeep` の観察で見る。

## やらないこと

- 検出した値を会話や報告に丸写しすること。報告が新しい漏れの経路になる
- 検出ゼロで「安全」と言うこと
- 利用者に聞かずに履歴を書き換えること、リポジトリの設定を変えること
- 非公開の名前の一覧をリポジトリに入れること
- 誤検知を黙らせるために `.publicallow` を増やすこと。足す前に中身を見る
- 走査が通ったことを理由に、画像と Wiki と Actions のログを見ないこと

## 他のスキルとの関係

- 鍵・トークンの走査と、見つかったときの対応順序: `secret-leak-check`
- PR のマージ前の確認の1つとして: `solo-pr-flow`
- 新しいリポジトリを public にするとき: `repo-bootstrap` のあとに `--all`
- Ciel 自身の見直し: `skill-upkeep`
- 人が見るもの、伏せ方、GitHub 側の設定、履歴の書き換え: `references/checklist.md`
