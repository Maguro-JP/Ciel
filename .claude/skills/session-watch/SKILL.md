# セッションの見張り

セッションは放っておくと溜まる。終わったのに残るもの、ルーティンは動くのに成果が増えないもの、落ちたまま止まるもの、
人の答え待ちで止まるもの。一覧を人が毎回読み分けるのは続かないので、機械で判定し、処置まで進める。

## 手順

1. 一覧を取って、ファイルに書く。`list_sessions(mine=true, limit=100)` と `list_triggers(limit=100)`（複数ページは配列をつなげる）の結果を、
   scratchpad の `sessions.json` と `triggers.json` に書く。MCP の一覧は Python から呼べないので、ここだけ手で写す
2. 判定する

```
python3 .claude/skills/session-watch/scripts/judge.py --sessions sessions.json --triggers triggers.json --clones /home/user --json actions.json
```

3. 処置する。`actions.json` の順に、消す → 起こす → 知らせる → 聞く

| 判定 | 根拠 | 処置 |
|---|---|---|
| サボり | 有効なルーティンに紐づき、直近の実行は成功なのに、そのリポジトリのデフォルトブランチに 3 日間コミットが無い | `fire_trigger` で 1 回起こす（text に「前回から成果が無い。今日の分を進める」）。同じ判定が 2 回続いたら、ユーザーに知らせる（理由は `post_turn_summary`。確認ゲートの「PR 待ち」が原因なら、そのブランチを ❔ に並べる） |
| 落ちた | `status_bucket` が FAILED で、理由が上限ではない | 紐づくルーティンがあれば `fire_trigger` で 1 回起こす。無ければ知らせる。落ちたまま 30 日以上なら「無駄の候補」 |
| 宙に浮いたルーティン | 有効なルーティンの紐づけ先が、アーカイブ済みか一覧に無い | 知らせる。無効にするか、セッションを戻すかはユーザー |
| 上限で止まった | 理由に weekly limit か rejected | 起こさない（patrol の決まり）。戻る時刻を書いて待つ |
| 動いたまま止まっている | RUNNING のまま 1 日以上動きが無い | 知らせる。`interrupt_session` は、ユーザーが言ったときだけ |
| 答え待ち | BLOCKED か REQUIRES_ACTION | 問いを 1 行で知らせる。答えるのはユーザー |
| 無駄 | AI が立てた（`parent_session_id`、tag `feedback-session:`・`ciel:`・`config:meta-mcp-own-entry`、origin が claude_code_mcp_seed）、ルーティン無し、3 日以上動いていない | `archive_session` で消す（`unarchive_session` で戻せる）。`feedback-session:keep` の付いたものは残す |
| 無駄の候補 | 人が開いて、ルーティン無し、30 日以上動いていない | 消してよいかを 1 回の ❔ にまとめて聞く。返事が「任せる」なら消す |
| 分からない | ルーティンの先のリポジトリの clone が手元に無い | 知らせる。clone を置けば次から判定できる |
| 回っている・動いている・待機 | 上のどれでもない | 無し |

4. 会話には 1 行: `★ セッション: 消した N、起こした N、知らせる N、聞く N`。知らせるものは 1 件 1 行（3 行を超えたらファイル）。
   聞くものは 1 つの ❔ にまとめる。処置が 0 なら ❕ で 1 行

## 決まり

- 消すのはアーカイブ。消せないもの（ツールの権限で止められた）は名前を書いてユーザーに任せる
- 起こすのは 1 回だけ。起こしても成果が出ないものは、人の判断が要る（プロンプト、枠、リポジトリ側の詰まり）
- 走っているセッションのブランチ・PR・ルーティンには触らない。判定と処置だけ
- 毎日の見回り（vuln-watch と同じルーティン）で回し、週 1 回の skill-upkeep で取りこぼしを拾う

## スクリプト

| 何 | すること |
|---|---|
| `scripts/judge.py` | 一覧から判定と処置を出す。`--days`（サボりと無駄の日数、既定 3）、`--stale`（人のセッションの日数、既定 30）。clone はデフォルトで取り直す（`--no-fetch` で止める。取り直さないと古い clone で動いているものがサボりに見える） |
| `scripts/test_judge.py` | 作った一覧と一時的なリポジトリで、判定と処置を確かめる |

## 他のスキルとの関係

- 全体を表で見る: `patrol`。止まっているかの判定の元はそこ。このスキルは処置まで進める
- ブランチ・一回きりのルーティン・終わったセッションの整理整頓: `tidy`。このスキルの「無駄」は tidy の「終わったセッション」と同じ判定で、毎日回す
- セッションを立てるときの設定と、立てた側での片付け: `feedback-session`
- 定期実行: `scheduler`。週の報告: `skill-upkeep`
