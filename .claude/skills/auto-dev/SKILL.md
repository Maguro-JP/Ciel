# Auto Dev

「自動で開発を進めて」を、そのまま回せる形に変える。

毎回プロンプトを組み立て直すのが面倒だから、**何を作業対象にするか、1周で
どこまでやるか、いつ止まるか**を先に決めておく。あとは繰り返すだけにする。

## 引数

```
/auto-dev
/auto-dev 2h
/auto-dev 2h テストを先に通して
/auto-dev 認証まわりを優先
```

| 形 | 意味 |
|---|---|
| 数字 + `m` `h` `d` | 時間制限。この時間を過ぎたら止まる |
| 省略 | 時間制限なし。止まる条件に当たるまで続ける |
| 残りの文字列 | 優先してほしい指示。作業の選び方に割り込む |

時間制限と優先指示は順不同。両方省略してもよい。

## 始める前に決めること

回し始める前に、次を確定させて利用者に一度だけ見せる。**ここを飛ばさない。**
何を勝手にやられるか分からない状態で放置させてはいけない。

```
自動で進めます。

  対象      : <リポジトリ>
  時間制限  : 2時間（10:30 まで）
  優先      : テストを先に通す
  作業の順  : 壊れているもの → 優先指示 → TODO と issue → 気づいた不備
  止まる条件: 下記に該当したとき
  報告      : 変化があったときだけ

これで回します。
```

## 1周でやること

**1周につき、作業は1つだけ。** 完了まで持っていく。中途半端なまま次に移らない。

1. 状態を見る。作業中のもの、壊れているものを確認する
2. 次の1つを選ぶ（下記の順序）
3. やる
4. 実際に動かして確かめる
5. コミットする。PR にするかは `.claude/policy/<利用者名>.json` の方針に従う
6. 変化があれば1〜3行で報告する。無ければ黙る

## 作業の選び方

上から順に見て、最初に当たったものをやる。

| 順 | 対象 | 補足 |
|---|---|---|
| 1 | 壊れているもの | CI が赤、テストが落ちている、ビルドが通らない |
| 2 | 詰まっているもの | マージできない PR、コンフリクト、レビュー指摘の未対応 |
| 3 | 優先指示 | 引数で渡されたもの |
| 4 | 明示された宿題 | issue、TODO、FIXME、ドキュメントに書かれた未着手 |
| 5 | 気づいた不備 | 3周に1回まで。ここばかりやらない |

**1と2を飛ばして新しいものを作らない。** 壊れたまま積み上げない。

## 止まる条件

**該当したら、その周で止めて報告する。次の周に進まない。**

| # | 条件 |
|---|---|
| S1 | 時間制限に達した |
| S2 | やる作業が無くなった |
| S3 | 同じ失敗を2回繰り返した。3回目を試さない |
| S4 | 設計の分岐に当たった。どちらでもよい選択肢が複数ある |
| S5 | 取り消しにくい操作が要る。データの削除、外部への公開、課金、認証情報の変更 |
| S6 | 依頼の範囲を超える。頼まれていない機能を足そうとしている |
| S7 | 判断の根拠が足りない。仕様が書かれていない、意図が読めない |
| S8 | 同じファイルを3周続けて触っている。堂々巡りになっている |
| S9 | 利用者から新しい指示が来た |

S3 と S8 が効く。**自動で回すと、直らないものを延々と直そうとする。**
2回で諦めて報告する方が、10回試すより早い。

止まるときは、何をどこまでやって、なぜ止まったかを書く。

## やってはいけないこと

- 頼まれていない大きな設計変更
- 無関係なリファクタ。ついでに直すのは、触ったファイルの中だけ
- テストを通すためにテストを緩めること
- 動作確認を省いて次へ進むこと
- 止まる条件に当たったのに「たぶん大丈夫」で続けること

## 報告

**変化があったときだけ書く。** 何もなければ黙る。

```
CI の赤を直しました。backend/app/main.py の未使用 import を削除。
次: issue #12 の入力検証
```

3行を超えない。経緯を再掲しない。差分が記録なので。

止まるときだけは、理由と次にどうしてほしいかを書く。

## loop との関係

繰り返しそのものは `/loop` が行う。このスキルは、その1周ごとに何をするかを決める。

```
/loop /auto-dev 2h テストを先に通して
```

間隔を指定しなければ、こちらのペースで決める。

- 待つものが無い → 20〜30分
- CI やデプロイの完了を待っている → その所要時間に合わせる
- 何かを走らせていて通知で起きられる → 長め（20分以上）の保険だけ

**短い間隔で様子を見に行かない。** 変化が無いのに起きるのは、時間と枠を捨てるだけ。

止まる条件に当たったら loop も止める。回り続けさせない。
