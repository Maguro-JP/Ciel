# 振る舞いの矯正表

ユーザーから指摘された振る舞いと、それを止める仕組み。
言葉（CLAUDE.md やスキル）だけでは長い会話で戻るので、戻ったものはフックにする。
週報（`skill-upkeep`）が「数で見るもの」の列を読み、減っていなければ仕組みを直す。

| 指摘された振る舞い | 止める仕組み | どこで効くか | 数で見るもの |
|---|---|---|---|
| 指示を優先しない、言うことを聞かない | `follow-instructions` の優先順位。`directives.py` がセッション内の指示を毎ターン差し込む。CLAUDE.md の「指示の優先順位」 | 毎ターン | 直させた回数（訂正の数） |
| 勝手に考える、自分の案を混ぜる | `follow-instructions` の「勝手に考えない」。`prompt-from-context` が対象と形を前の会話から補う | 依頼の直後 | 聞き返し（❔）の数 |
| 訂正されても改めない、言い返す | `follow-instructions` の「訂正を受けたとき」と「反抗の禁止」。`done_check.py` が訂正への返事に反論の形があれば差し戻す | 返答の最後 | 反論の数 |
| 反抗する、拒む、AI の判断で止める | `follow-instructions` の「反抗の禁止」の表。CLAUDE.md の「反抗を禁止する」「AI の基準で止めない」 | 毎ターン | 反論の数 |
| 自分に権限を付与する | `no_self_grant.py`（PreToolUse）。`docs/PERMISSIONS.md` | 書き込みの前 | 止めた回数 |
| 成果物が何か月も完成しない | `finish-first`。`focus.py` が今の成果物を毎ターン差し込む。`auto-dev` の判断表の 4 | 毎ターン | 完成した成果物の数 |
| 手を抜く、一部だけやる | `directives.py` が指示の数を数えて差し込む。`done_check.py` が、指示が 2 つ以上あるのに ★ も ↩ も無い返事を差し戻す | 依頼の直後と返答の最後 | 指示の数と ★↩ の数 |
| できたと言って、できていない | `done_check.py` が完了の語（マージした、push した、コミットした、通った、直した）を、このターンのツールの出力と照合し、無ければ差し戻す。`verify-before-done` の表 | 返答の最後 | 出力に根拠の無い語の数 |
| 見ていないのに、見たと言う | `done_check.py` が「見た」「確認した」「読んだ」のある返答で、ツールを 1 つも呼んでいなければ差し戻す | 返答の最後 | 同上 |
| 出力と逆のことを言う（落ちているのに通った） | `done_check.py` が、出力に FAILED や誤りがあるのに「通った」と書いた返答を差し戻す | 返答の最後 | 矛盾の数 |
| 出したあとに間違いが分かる（PR 番号の直し、実行権限、落ちる配布スクリプト） | `precheck.py` が検査を 1 本で通して記録し、`pr_gate.py` が記録とユーザーの確認（❔ と返事）の無い PR の作成・マージ・main への push を止める。`solo-pr-flow` の「出す前の確認」 | PR・マージ・push の前 | 出したあとの直しの数（同じ PR への 2 回目以降のコミット） |
| 散らかす（表だけの PR、増える配布ブランチ、出したあとの直しのコミット） | `tidy` の「散らかさない」の表。表・週報・lessons は同じ PR に入れ、配布ブランチは 1 日 1 本。`pr_gate.py` が頼まれていない Release やタグの作成を止める | PR とブランチを作る前 | 1 日の PR の数と、残っているブランチの数（週報） |
| 同じ文言を繰り返す（毎ターンのフックの差し込み、❔ の出し直し） | lang-rule は 10 ターンに 1 回と止められた直後、directives は 3 件 80 文字、focus は 300 文字、CORE は 10 ターンに 1 回、lessons は 12 件。`measure_hooks.py` で測る。❔ の出し直しは前の ❔ を指す | 毎ターン | 1 ターンの差し込みの文字数 |
| README や docs が古い（壊れたリンク、無い一覧、予定のまま） | `docs-upkeep` の `docs_check.py` が validate と precheck で止める。スキルを足した PR で一覧を直す | PR の前 | 誤りの数 |
| 長く回すと散らかる | `tidy` の「月に 1 回の整理整頓」。`tidy_report.py` が消せるブランチ、余計なファイル、古い判断待ちと PR を集め、long-dev と skill-upkeep のルーティンが月の最初の回に整理整頓して月報に書く | 月の最初の実行 | 月報の「整理整頓」の節の件数 |
| スキルどうしが干渉する | `docs/GUIDELINES.md` の 10 の表でどちらに従うかを決める。skill-audit と skill-upkeep が足すときに見る | スキルを足す・直すとき | 表の行数 |
| できたと言ってから、間違えていたと言う | 上の照合で、出力の無い「できた」が出なくなる。撤回は差し戻さず数だけ残す（正直に言い直すのを止めない） | 返答の最後 | 撤回の数 |
| できないと言う | `follow-instructions` の「できないと言う前に」（別のツールと経路を1回ずつ）。`docs/PERMISSIONS.md` の書き方 | 止まったとき | ― |
| 無駄が多い、通知の洪水、長い返事 | `token-efficiency`。4 種類のマーク。通知だけの返事は1行。`solo-pr-flow` の購読解除はマージのあと | 毎ターン | 会話の形から外れた数 |
| 予定を書く（「〜します」） | `work-style` の「会話に出すもの」。`done_check.py` が数える | 返答の最後 | 予定の行の数 |
| 聞き返す、判断待ちに回す | `prompt-from-context`、`finish-first`。`done_check.py` が ❔ 2 つ以上を差し戻す | 返答の最後 | ❔ の数 |
| 短い一言を文字どおりに読む | `prompt-from-context`。`brief.py` が直前の文脈を差し込む | 短い一言のとき | 短い一言の数と聞き返し |
| 脆弱性のニュースに気づかず、更新が遅れる | `vuln-watch`。`scan.py` が毎日、全リポジトリの依存を OSV・CISA KEV・JVN に突き合わせ、新しいものに ★ を付けて周知する。悪用済みと重大は通知し、`bump.py` で更新のブランチを用意する | 毎日のルーティン | 新規の件数と、見つけてから更新の PR までの日数 |
| 日本語が崩れる、訳語を作る、英語の出だし | `lang-rule.sh`、`lang-check.sh`、`ja-proofread` | 毎ターンと返答の最後 | proofread の重大の数 |
| ユーザーが使わない略語・訳語・造語で書く（「プルリク」「リポ」「Routine」「片付け」「JST」） | `user-terms` の対応表。`terms_check.py` が返答を表と突き合わせて差し戻し、`terms.py --diff` が文書の差分を注意で出す。`terms_learn.py` が発言の語を数えて表を育てる | 返答の最後と PR の前 | 差し戻した語の数（metrics.jsonl）と文書の注意の数 |
| CLI やブラウザで作る | `desktop-app`。`no_browser.py`（PostToolUse） | 書き込みのあと | 止めた回数 |
| 時刻を UTC で書く | `lessons` の記録と CLAUDE.md | 毎ターン | ― |

同じ指摘がまた来たら、この表に行を足し、言葉ではなくフックで止める。
