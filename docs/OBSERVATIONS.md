## 読み取れたこと

### 1. 500行はほぼ守られている

271本中、500行超はわずか **7本**（2.6%）。公式ガイドの「500行以内」は努力目標ではなく
**実際に守られている実務基準**だった。中央値168行が実勢。

### 2. description は 20〜60語が主戦場

47語（中央値）。10語未満はほぼ存在せず、100語超も31本と少数派。
**40字未満は短すぎ、150語超は薄まる**、という感覚は実測と一致する。

### 3. トリガ句は 85% が明示している

"Use when 〜" のような定型句を description に入れるのが事実上の標準。
入れていない15%は主に Anthropic 公式（38%）で、代わりに具体名詞を密に置く書き方をしている。
**どちらでもよいが、慣れないうちは定型句を使う方が安全**。

### 4. 除外句は全体で39%。ただし Google は75%

スキル数が多い提供元ほど除外句を書いている。108本を運用する Google が突出しているのは示唆的で、
**スキルが増えるほど誤爆が問題になり、除外句が必須になる**と考えられる。
Ciel も本数が増えたら除外句を必須級に格上げすべき。

### 5. scripts/ は9%、しかし Anthropic だけ44%

「スクリプトを同梱して確定動作にする」は**全体では少数派だが、公式では標準的**。
PDF・Excel など決定的な処理が必要な領域に集中している。
上級テクニックではなく「必要な領域では必ずやる」もの、と解釈するのが正しい。

### 6. references/ の使い方は領域で割れる

Marketing（83%）や Google（54%）は分厚い資料を分離する。
PM skills は 0% で、本文78行と短く完結させている。
**本文が短いなら references は要らない**。分離は肥大化への対処であって、様式美ではない。

### 7. frontmatter の拡張フィールド

```
metadata       156本    license  20本
compatibility    3本    references 2本    allowed-tools 1本
```
`metadata` が過半で使われている一方、`allowed-tools` は1本のみ。
**name と description 以外は実質使われていない**と考えてよい。

## 発動の仕組み（Anthropic 公式 skill-creator より）

description の質とは別に、**タスクの重さ**が発動条件になる。

> Claude は自力で簡単に処理できないタスクにしかスキルを参照しない。
> 「このPDFを読んで」のような単純な1ステップの依頼は、description が完璧に一致していても
> 発動しないことがある。基本ツールで直接処理できてしまうから。
> 複雑・多段階・専門的な依頼なら、description が一致していれば確実に発動する。

実務上の帰結:

- **軽い作業のスキルは作っても呼ばれない**。スキルは面倒な多段階作業に効く
- 発動テストを「ファイルXを読んで」のような軽い依頼で行うと、
  何を直しても発動しないので評価にならない

## 三層のロード（公式定義）

| 層 | 内容 | タイミング | 目安 |
|---|---|---|---|
| 1 | name + description | **常時** | 約100語 |
| 2 | SKILL.md 本文 | 発動時 | 500行以内 |
| 3 | references / scripts / assets | 必要時のみ | 無制限（スクリプトは読み込まずに実行可） |
