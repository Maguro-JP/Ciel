## 知識
見せかけは、形で拾える。ただし「今ある形」を全部止めると、前からある物と、理由のある物で偽の当たりになる。止めるのは「このターン（この差分）で足して、今も残っている形」だけにする。
足した行だけを見る。消した行にも同じ文がある行は、動かしただけ（インデント、移動）なので、足した行に数えない。base と比べるときは `git merge-base` で分かれ目を取る。
base の先頭と比べると、base が足したテストは「消した」に、base が消した握りつぶしは「足した」に見える。

重さは、理由が読めるかで分ける。型を絞った except、規則を名指しした抑止、条件つきの skip は、理由が読めるので止めない。まるごとの握りつぶし、まるごとの抑止、条件なしの skip は止める。
名指しの抑止を止めると、実際の履歴のコミットの多くが当たる（このリポジトリの履歴で 104 行）。

消した物は、行が残らないので、足した行の検査では見えない。前の中身と今の中身から名前（関数、クラス、export、テスト、ルート）を取り出して引く。
同じ名前が、変えたファイルのどれかに今あれば、移しただけ。フックの登録は、文字の並びではなく、動かすスクリプトの名前で突き合わせる。書き方を変えただけの登録を、消したと数えないため。

差し戻しは、禁止ではなく「隠さずに 1 行書く」にする。機械は、仕様が変わったのか、出力に合わせただけかを見分けられない。消した・弱めた・残した、を返答に 1 行書かせれば、人が見分けられる。
偽の差し戻しの費用も、1 行で済む。

配るスキルでは、配った先の `.claude/skills/` はコピーなので見ない。コピーの中の形で止めると、配った先の全部で同じ検査が落ちる。

テストが効いているかは、通るだけでは分からない。対象の 1 か所を壊したコピーで流して、落ちるのを見る。落ちなければ、そのテストは壊した所を見ていない。

使えない場合: Bash で書き換えた中身（`sed -i`、ヒアドキュメント）は、フックからは見えない。差分の検査（precheck）が拾う。JavaScript と TypeScript は文字列とコメントを落としてから形で見るので、
正規表現のリテラルや JSX の文の中の引用符で、切り分けを誤ることがある。配線されていない物は、名前がほかに出てこないことで見るので、名前を文字列から組み立てて呼ぶ物は偽の当たりになる。
会話の記録の欄（`originalFile`）は文書に無く、版で変わり得る。subagent の記録には無い。

## アルゴリズム
差分の検査（`fake_scan.py --diff <base>`）。入力は base とリポジトリ。出力は形の一覧と、重大があれば終了コード 1。
1. `git merge-base <base> HEAD` で分かれ目を取る。取れなければ base のまま
2. `git diff -U0 -M <分かれ目>` で、ファイルごとに足した行と消した行と、かたまりの番号を取る。追跡していない新しいファイルは、全部の行を足した行にする
3. 配った先の `.claude/skills/` の中と、見ない場所（`node_modules`、`fixtures`、形の表）を落とす
4. 足した行から、同じファイルの消した行にある文と、差分のどこかの消した行にある 9 文字以上の文を除く（動かしただけの行）
5. 変えたファイルの今の中身を、形で見る。Python は ast（関数の中身、except の中身、テストの関数、デコレータ）、JavaScript と TypeScript は文字列とコメントを落とした文、コメントは別に取り出す
6. 形の始めの行から終わりの行のどれかが、4 の足した行にある形だけを残す。`no-fake: ignore` のある形は落とす
7. 消した行から、テストを消した（同じかたまりに新しいテストの定義があれば名前の変更）、assert の減り、期待値の書き換え（数と文字列を落とした形が同じ）、しきい値、フックの登録、CI の段を出す
8. 新しい関数の名前と新しいファイルの名前が、追跡しているファイルのほかの所に出てくるかを数える
端の場合: 構文が壊れたファイルはコメントだけ見る。追跡しているファイルが 6,000 を超えたら 8 を数えず、数えなかったと出す。費用: git の呼び出し 3 回と、変えたファイルの読み。8 は追跡しているファイルを 1 回ずつ読む。

ターンの終わりの差し戻し（Stop）。入力は会話の記録と最後の返答。出力は通す（0）か差し戻す（2 と 1 行）。
1. `stop_hook_active` が真か、記録が無いか、common-sense の `_cs.py` が無ければ通す
2. 記録の後ろ 1MB から、最後の人の発言より後ろを 1 ターンとして取る（通知と差し戻しは人の発言に数えない）。人の発言が見つからなければ 8MB、全部と広げる
3. 成功した Edit・Write・MultiEdit を、ファイルごとにまとめる。最初の編集の `originalFile` が、ターンの始めの中身
4. ファイルごとに、ターンの始めの中身と今のディスクの中身を比べて、足した行と消した行を作る。差が無ければ（途中で戻した）見ない。リポジトリの外のファイルは見ない
5. 足した行の形（差分の検査の 4〜7）と、消えた名前（前の名前 − 今の名前。移した物を除く）と、Bash の `rm` で消えた追跡していたファイルを出す
6. コードのファイルを変えていれば、最初の変更より後ろに、動かす呼び出し（テスト、起動、スクリプト。引用の中の語は見ない）があるかを見る
7. 返答に、形ごとの行（`❕ 見せかけ:`、`❕ 弱めた:`、`❕ 消した:`、「動かしていない」）が無い物だけを、1 行にまとめて差し戻す。拾った数を種類ごとに記録する
端の場合: `originalFile` が無い記録では、置き換えの前後の文から足した行と消した行を作る。一言が 600 文字以下のときだけ、頼まれた置き場と頼まれた削除の語を探す。

変える前との比べ（`baseline.py`）。入力はテストの出力。出力は、通っていたのに落ちた名前。
1. テストのコマンドを探して流す（pytest、スキルの元のリポジトリのスキルのテスト、unittest、npm test）。無ければ何も出さない
2. 出力の行から、名前と、通った・落ちたを取る。同じ名前が 2 回出たら落ちた方
3. save は名前の一覧を置き、compare は、前に通って今落ちた・前に通って今無い・前に無くて今落ちた、に分ける。1 つ目があれば終了コード 1

## 実装
- no-fake のスキルとして入れ、`.claude/settings.json` とひな形に登録した（PostToolUse の `fake_nudge.py`、Stop の `fake_gate.py`）。precheck に `fake_scan.py --diff` の 1 段を足した
- テストの出力: `Ran 44 tests in 4.400s` `OK`（test_fake_scan.py）、`Ran 34 tests in 4.861s` `OK`（test_hooks.py）、`Ran 10 tests in 0.716s` `OK`（test_removed.py）、`Ran 14 tests in 1.445s` `OK`（test_baseline.py）
- 対象の 1 か所を壊したコピーで流した出力: `壊した 14 か所 / テストが落ちなかった 0`。最初は 1 か所が落ちなかった。分かれ目を取らない形に壊しても、base が足した握りつぶしは「消した」側に出るだけで、テストが見ていなかった。base が足したテストと、base が消した握りつぶしの組に直して、落ちるようになった
- 実際の会話の記録 4 本（親のセッションと subagent 3 本。編集の呼び出し 142、見た変更 51 ファイル、足した 5,113 行、消した 51 行）に判定を当てた出力: 知らせ 0、差し戻し 0
- このリポジトリの履歴に、コミットを 1 回の変更と見て当てた出力: `見たコミット 94 / 重大のあるコミット 3 / 形ごとの数 {'S01 重大': 7, 'S02 注意': 40, 'S04 注意': 4, 'S05 注意': 6, 'T04 重大': 1, 'T08 注意': 2, 'W03 重大': 1, 'W13 注意': 104}`。重大の 3 件は、握りつぶしを足したコミット、テストを 2 つ消したコミット、`# type: ignore` を足したコミット
- 履歴に当てる前は、重大のあるコミットが 6 件で、3 件が偽の当たりだった。フックの登録の書き方を変えただけ（起動役を通す形にした）のコミットを、登録を消したと数えていた。スクリプトの名前で突き合わせる形に直した
- リポジトリ全体に当てた出力: `見せかけの確認: 重大 8 / 注意 29`（握りつぶし 7、まるごとの抑止 1。どれも前からあるフックの中）。このブランチの差分に当てた出力: `見せかけの確認: 重大 0 / 注意 36`
- 差分に当てて見つけた偽の当たり: 小文字の `todo` を置き場のマークとして拾っていた（TAP の `# todo` の説明のコメント）。大文字のマークと `todo:` の形だけにした
- 配った先の形（そのリポジトリ自身の登録がある settings.json、そのリポジトリ自身のテストは無い）のコピーに sync.py で配り、そこで動かした出力: テスト 4 本が `OK`、`フックの誤り 0`、無害な入力でフック 2 本が出力 0 文字、`baseline.py` が出力 0 文字、スキルを入れたコミットの差分が `見せかけの確認: 重大 0 / 注意 1`
- 差し込みの量: `SessionStart 合計 3848 文字（目安 5000）: 目安内`、`UserPromptSubmit 合計 1065 文字（目安 1200）: 目安内`。no-fake のフックは PostToolUse と Stop だけなので、普段のターンは 0 文字。形を見つけたときだけ 1 行
