# フックの登録は、作業ディレクトリに頼らない

- 日付: 2026-11-14
- 語: フック, hook, 作業ディレクトリ, cwd, cd, CLAUDE_PROJECT_DIR, 終了コード 2, run.sh, 子のセッション

## 情報
- フックは今の作業ディレクトリで動く。フックの入力の cwd は、cd したあとの場所に付いていく。`CLAUDE_PROJECT_DIR` は、セッションを始めたプロジェクトの根を指し、フックの子プロセスに渡される。プロジェクトの台本は `"$CLAUDE_PROJECT_DIR"/.claude/hooks/x.sh` の形で指すのが勧められている（https://code.claude.com/docs/en/hooks 、2026-11-14）
- 終了コード 2 は、PreToolUse ではツール呼び出しを、Stop では終了を、UserPromptSubmit では一言を止める（同じ文書）
- 動かして確かめた: 親から分けた子のセッションの 1 本が、開始 1 分で「cd のあとの相対パスでフックが失敗」と報告して止まった。登録は `python3 .claude/skills/...` の相対パスで、python3 は無いファイルに終了コード 2 を返す
- `CLAUDE_PROJECT_DIR` が全部の event で渡されるかは、文書の読んだ範囲では明記が無い。渡されないときは今の場所のまま動かす形にした

## 知識
相対パスで登録したフックは、会話の途中で cd すると見つからなくなる。見つからないときの python3 の終了コードが 2 なので、フックの世界では「止める」になり、全部のツール呼び出しが止まる。cd で戻る呼び出しも止まるので、自分では抜けられない。
登録は、根に戻ってから動かす起動役を通す。起動役は、無いフックを 0 で終える（スキルを消したあとに残った登録で止まらないように）。止める判定（フック自身の 2）はそのまま伝える。
使えない場合: フックが、今いる場所そのものを見たいとき（worktree の中の状態など）。そのときは入力の cwd を読む。

## アルゴリズム
入力はフックのパス（根からの相対）と引数。出力はフックの終了コードと出力そのまま。
1. `CLAUDE_PROJECT_DIR` があればそこへ cd する。無ければ今の場所のまま。cd に失敗したら 0 で終える
2. パスが空か、ファイルが無ければ 0 で終える
3. `.py` なら python3 で、それ以外はそのまま exec する（標準入力と終了コードがそのまま渡る）
配るときの手順: 対象の登録のうち、ひな形と中身（フックのパスと引数）が同じで起動の仕方が古い物を、ひな形の形に置き換える。足すと同じフックが 2 回動くので、足さない。そのリポジトリ自身のフックには触らない。
端の場合: 起動役そのものが無いと、シェルが 127 を返す（止める意味にならない）。awk のように台本でない登録は、先頭に cd を付ける。

## 技術
- 場所: `.claude/hooks/run.sh`（起動役。ひな形にも同じ物）
- 場所: `.claude/skills/skill-sync/scripts/sync.py` の `core` と `reanchor`（古い登録の置き換え）
- 場所: `scripts/hooks-smoke.py`（起動役を通していない登録を誤りにし、別の作業ディレクトリからも 1 回動かす）
- テスト: `.claude/skills/skill-sync/scripts/test_sync.py`

## 実装
- `.claude/settings.json` とひな形の登録を、全部この形に替えた（台本は起動役、awk は先頭に cd）
- 別の作業ディレクトリから動かした出力: `from other cwd exit=0`、無いフック: `missing file exit=0`
- validate のフックの検査が、全部の登録を別の作業ディレクトリからも動かす
